# 연구 진행 방향 (Canonical) — 2026-06-12

이 문서는 DocViz-Agent / QG-MDV 연구의 현재 확정된 진행 방향을 담는다. 이전의 작업 메모
(STRATEGY_reframe, VIZ_EVAL_METRICS_survey, METHOD_agentic_tools)는 조사 기록이며, 실제
실행의 기준은 이 문서다.

---

## 1. 핵심 프레이밍

본 연구가 다루는 과제는 다문서 질의 기반 시각화(Query-Grounded Multi-Document Visualization)
이다. 여러 문서에 흩어진 정보를 통합하여, 사용자 질의에 부합하고 모든 시각적 요소가 출처
문서에 근거된 시각화(차트 또는 도식)를 생성하는 것이 목표다.

본 연구의 핵심 주장은 다음과 같다. **다문서 시각화에서 어려운 부분은 시각화를 그리는 단계
(렌더링)가 아니라, 그리기 이전에 여러 문서로부터 올바른 데이터를 구성하는 단계다.** 구체적으로,
서로 다른 문서에 분산되어 있고, 중복되며, 때로 상충하고, 단위·스케일·시점이 제각각인 정보로부터
정확하고 완전하며 출처가 추적 가능한 중간 데이터를 만들어내는 것이 본 과제의 본질적 난점이다.

이 주장은 실험으로 뒷받침된다. 시각 구조의 품질을 재는 DiagramEval의 노드·경로 정렬 점수는
모든 비교 대상에서 비슷한 수준으로 수렴하여(즉 렌더링·구조 생성은 모든 모델이 어느 정도 해낸다),
변별력이 약하다. 반면 출처 귀속 점수(Evidence F1)는 제안 방법이 모든 출처에서 압도적으로 높다.
다시 말해 **모델 간 차이는 "잘 그리는가"가 아니라 "데이터를 옳게 구성하고 근거를 대는가"에서
발생한다.** 이것이 본 연구의 위치이자, 단일 문서 차트 생성 연구나 텍스트 기반 다문서 질의응답
연구와 본 과제가 구별되는 지점이다.

## 2. 방법 (DocViz-Agent의 도구 기여)

본 과제의 본질적 난점이 "다문서 데이터 구성"이라면, 방법의 기여는 그 데이터 구성을 수행하는
에이전트 도구여야 한다. 우리는 가장 가까운 선행 방법을 채택하되 우리 환경(다문서 입력 + 출처
귀속 + 시각화 출력)에 맞게 확장한다. 그대로 가져다 쓰지 않는 이유는, 차별점을 명확히 하여
"이미 있는 방법 아니냐"는 심사 공격을 차단하기 위해서다.

**교차 문서 반복 추출·검증 도구.** Doc2Chart(EMNLP 2025)는 사용자 의도를 분해한 뒤 문서에서
관련 정보를 추출하고, 정확성·완전성·관련성을 검증하여 재추출하는 2단계 절차를 제안했다. 그러나
Doc2Chart의 검증은 단일 문서 안에서의 정합성에 머문다. 우리는 이를 **여러 문서에 걸친 추출**로
확장하고, 검증 루프에 **문서 간 상충 탐지**를 추가하며, 추출된 각 값에 **출처 식별자**를 부착한다.

**주장 군집화를 통한 시각 계열(series) 조립.** 다문서 요약의 명제 수준 군집화(Proposition-Level
Clustering, NAACL 2022)는 문서들에서 명제를 추출하여 의미가 같은 것끼리 묶고 하나의 문장으로
융합한다. 우리는 융합(요약)이 목적이 아니라, **같은 (개체, 지표, 시점)에 관한 주장들을 묶어
하나의 시각 계열 원소로 매핑**하는 것이 목적이다. 군집 내 출처는 보존하고, 중복 계열은 제거한다.

**충돌 조정(Conflict Adjudication).** 다문서 요약·질의응답 문헌은 상충 정보를 난점으로 지적하지만
이를 시각화 생성을 위해 해소하는 방법은 제시하지 않았다. 우리는 (개체, 지표, 시점) 셀에서 문서
간 값이 충돌할 때 이를 탐지하고, 정책(최신성·출처 권위·다수결)에 따라 어떤 값을 인코딩할지
결정하며, 해당 시각 요소에 충돌 표시와 출처를 부착하는 도구를 제안한다. 이는 신규 기여이며,
모순 해소 유형(Type E) 질의로 직접 평가할 수 있다.

**출처 귀속 출력(Source-Attributed Output).** 각 데이터점·노드·엣지에 출처 식별자를 부착한다.
이는 생성 단계에 내재된 메커니즘이며(평가용이 아니라), 본 연구의 출처 귀속 결과의 토대다.

핵심 기여는 위 네 도구 중 **교차 문서 데이터 구성**과 **충돌 조정** 두 가지다. 이 둘은 단일 패스
생성이나 단일 문서 방법이 구조적으로 수행할 수 없는 능력이므로, 성능 우위(SOTA) 주장의 근거가
된다. (TMG, VSC는 헤드라인 기여에서 제외한다.)

## 3. 평가 (두 축, 모두 비어휘적 매칭)

본 연구의 평가는 두 축으로 구성되며, 두 축 모두 어휘(문자열) 매칭에 의존하지 않는다. 어휘 매칭은
개방형 생성에서 라벨 표현이 달라지면 깨지기 때문이다(이전 검토에서 확정).

**시각 축 — 렌더링된 이미지 기반.** 생성된 시각화를 실제로 렌더링한 뒤 평가한다.
첫째, DiagramEval(노드·경로 정렬)은 이미지에서 시각 언어 모델이 그래프를 추출하고 의미(코사인)
정렬로 채점하므로 어휘 매칭이 아니다. 구조 충실도를 잰다. 둘째, **VisJudge**(충실도-표현력-미학
프레임워크의 시각 언어 모델 심사자)는 렌더링 이미지를 직접 평가한다. 이 축의 역할은 "시각·구조
품질은 모델 간에 비슷하게 포화되어 있다"는 점을 보이는 것이며, 그래야 변별이 데이터·근거 축에서
일어난다는 서사가 성립한다. VisJudge는 우리가 만든 심사자가 아니라 인간 일치도(약 0.69)가 검증된
외부 공개 심사자이므로, DiagramEval과 마찬가지로 "자체 평가 정당화" 부담이 없다. (트리형 도식에는
보조적으로 트리 편집 거리(Tree Edit Distance)를 둘 수 있다.)

**데이터 축 — 출처 식별자 기반.** 본 연구의 기여가 데이터 구성이므로 핵심 측정은 이 축이다.
첫째, Evidence F1은 출처 귀속의 정확도를 식별자 집합 연산으로 잰다(헤드라인). 둘째, **귀속 값
충실도**는 각 데이터점의 값이 그 데이터점이 인용한 출처와 일치하는지를 잰다. 이는 Doc2Chart의
CHARTEVAL이 제시한 "차트 값을 출처로 역추적한다"는 아이디어를 채택하되, CHARTEVAL의 원래 구현
(생성 표를 정답 표에 어휘로 정렬)이 아니라 **모델 자신이 부착한 출처 식별자를 기준으로** 값의
일치를 수치 허용오차로 확인하는 방식으로 변형한 것이다. 이렇게 하면 라벨 어휘 매칭과 표 정렬
문제를 모두 피하면서 데이터 충실도를 측정할 수 있다.

요약하면, 시각 축(DiagramEval + VisJudge)은 "잘 그렸는가"를, 데이터 축(Evidence F1 + 귀속 값
충실도)은 "데이터가 옳고 추적 가능한가"를 잰다. 두 축 모두 비어휘적이며, 차트와 도식 양쪽에
적용된다(귀속 값 충실도는 수치를 갖는 차트에 한정하고, 도식은 시각 축과 Evidence F1로 평가).

## 4. 현재 결과와 SOTA 논리

세 출처(Loong, DocHop-QA, MultiHop-RAG)에서 비교 대상 B1–B7을 단일 시드로 측정 완료했다.
출처 귀속(Evidence F1)에서 제안 방법은 세 출처 전부에서 최강 비교 대상을 크게 앞선다(0.41 /
0.77 / 0.88 대 약 0.00 / 0.14 / 0.04). 시각 구조(노드·경로)는 모델 간 경쟁적이며 변별력이 약하다.

다만 현재의 Evidence F1 측정에는 한 가지 선결 과제가 있다. 제안 방법은 명시적 출처 식별자를
출력하고 비교 대상은 임베딩 매칭으로 추정 귀속을 받는, 비대칭 측정이다. 이 비대칭이 점수 격차를
부풀렸을 수 있으므로, **모든 비교 대상에 동일하게 출처를 인용하도록 지시한 뒤 대칭 조건에서
재측정**해야 한다. 대칭 조건에서도 격차가 유지되면 이는 능력 차이(본질적 발견)이고, 좁혀지면
명시적 귀속 메커니즘의 효과로 정직하게 서술한다. 이 재측정이 헤드라인의 성립 여부를 가른다.

SOTA 주장은 "더 나은 생성기"가 아니라 **"데이터 구성이 어려운 사례에서의 우위"**로 한다. 검증
가능한 예측은, 제안 방법의 우위가 데이터 구성이 어려운 질의 유형(방해 문서 다수, 모순 해소,
다단계 추론)에 집중되어야 한다는 것이다. 기존 세 출처 결과를 질의 유형별로 분해하면 즉시 확인할
수 있다. 각 도구의 제거 실험(교차 문서 추출 제거, 충돌 조정 제거 등)이 이 어려운 유형의 성능을
떨어뜨림을 보이면 도구의 필요성이 입증된다(제거 실험은 복구 산출이 아닌 네이티브 산출 기반이어야
한다).

## 5. 차용 평가의 기존 점수 활용 (검증·효율)

차용하는 평가(DiagramEval 등)의 원 논문에 이미 점수가 있는지, 우리 점수와 크게 다르지 않은지를
확인하는 것은 두 가지로 유용하다.

첫째, **지표 구현 검증**이다. DiagramEval 원 논문은 자신들의 도식 벤치마크에서 여러 모델의
노드·경로 정렬 점수를 보고한다. 우리가 DiagramEval 구현을 그들의 공개 테스트셋에 돌려 보고값을
재현하면, 우리 채점 파이프라인이 올바름을 검증할 수 있다. 이는 반드시 수행한다.

둘째, **외부 보류(held-out) 벤치마크에서의 비교 대상 재사용**이다. 우리 자체 벤치마크
(QG-MDV)에는 어떤 선행 논문도 점수를 보고한 적이 없다. 비교 대상 B1–B4는 원 방법을 우리
다문서 과제로 이식한 적응판이고, 측정도 우리 지표(DiagramEval 등)로 하기 때문에, **자체
벤치마크에서는 비교 대상 평가를 생략할 수 없다.** 그러나 외부 보류 벤치마크(Doc2Chart,
Text2Vis 등)에서 **그 벤치마크의 원래 지표와 프로토콜을 그대로 따른다면**, 원 논문이 보고한
비교 대상 점수를 인용하고 우리 방법만 새로 돌리는 것이 가능하다. 이 경우에도 인용 전에 우리가
재현한 한두 개 모델 점수가 보고값과 비이상적으로 크게 다르지 않은지 먼저 확인한다. 점수가 크게
어긋나면 프로토콜 불일치를 의심해야 하며, 그대로 인용하면 안 된다.

요지: 자체 벤치마크에서는 전 비교 대상 측정이 필수이고, 외부 보류에서는 원 지표를 따를 때에
한해 비교 대상 점수 인용으로 측정을 줄일 수 있다.

## 6. 다음 단계 (우선순위)

1. 대칭 조건 출처 귀속 재측정: 모든 비교 대상에 출처 인용을 지시하고 Evidence F1을 다시 잰다.
   현재 헤드라인의 성립 여부를 결정한다.
2. 질의 유형별 분해: 기존 세 출처 결과를 유형별로 나누어, 어려운 유형에서 우위가 큰지 확인한다.
3. DiagramEval 구현 재현 검증: 공개 테스트셋에서 보고값을 재현하여 채점기를 검증한다.
4. 충돌 조정 평가: 모순 해소 질의의 정답 측면 인코딩 정확도를 비교 대상별로 측정한다.
5. 교차 문서 추출·충돌 조정 도구의 상세 설계와 구현(Doc2Chart 2단계 절차의 다문서 확장으로 명시).
6. VisJudge 도입: 외부 공개 심사자를 비교 대상 풀과 분리하여 시각 품질 축을 측정한다.
